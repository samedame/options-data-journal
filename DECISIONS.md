# DECISIONS

Every judgment call, with the reasoning. Items marked **(deviation)** differ from the literal master prompt.

## Repo, tooling, dependencies

1. **Location.** `~/options-data-journal` (a sibling of the BotDeck checkout, *not* nested inside `Trading Bot Frontend`, so BotDeck's git history and my edits stay separate). Private GitHub repo `samedame/options-data-journal` is created if `gh` is authenticated (it was); otherwise the exact commands are in `README.md`.
2. **Python 3.12, exact pins** in `requirements.txt` / `requirements-dev.txt` (direct dependencies only). `scipy` was added for `ndtr`/`rankdata`; the greeks tests deliberately use an *independent* `math.erf` implementation so the numerical code is not checked against itself.
3. **mypy `strict = true` on `src/`**, ruff rules `E,F,W,I,B,UP,SIM,C4,RUF` (noisy `SIM102/105/115`, `RUF001-3` off). The vendored `client.py` is exempt from `UP` rewrites on purpose: it must stay valid on the older Pythons your bot repos may run.
4. **GitHub Actions are pinned to major tags** (`actions/checkout@v5`, `setup-python@v6`), not commit SHAs. Trade-off: convenience over supply-chain pinning; pin SHAs if you want that.
5. **Checkouts use `fetch-depth: 50`** so jobs stay fast as the repo grows; `odj ci publish` only needs recent history to rebase.

## Module A – snapshotter

6. **Slots** live in `config/tickers.yml`: `open` 09:45 ET, `close` 15:50 ET with `clamp_to_close_minutes: 10`, so on half-days the late slot moves to 12:50 (before the 13:00 bell) instead of being skipped. Window = slot time … +40 min (GitHub cron drift tolerance). All checks are in `America/New_York`, so DST cannot shift anything; the workflow has both UTC offsets per slot and the script exits quietly in the wrong one. A tiny shell gate in `snapshot.yml` makes the wrong-offset cron cost seconds instead of an install.
7. **File naming** uses the *effective* slot time (`0945`, `1550`, `1250` on half-days) while the row column `slot` is `open|close`. Idempotency key = (underlying, date, slot) and also looks inside compacted manifests.
8. **Model.** Black-Scholes-Merton with continuous dividend yield; T = ACT/365 to **16:00 ET on the expiry date** (SPY/QQQ/IWM are PM-settled; AM-settled index products such as SPX are *not* supported). SPY/QQQ/IWM options are American style, so BSM is an approximation – deep-ITM puts and ex-dividend calls will show `iv_divergence` / `parity_violation`, which is exactly what those flags are for. `iv_calc` is solved from the **mid** by vectorized bisection; **greeks are computed from `iv_calc`** (so no IV ⇒ no greeks). `theta` is per calendar day, `vega` per vol point.
9. **Inputs.** Risk-free rate = `^IRX / 100`; dividend yield = Yahoo `trailingAnnualDividendYield` (measured live: SPY 0.75%, QQQ 0.26%, IWM 0.72%; values > 25% are treated as percent). If either is unavailable the config default is used, the snapshot is stamped `greeks_inputs_defaulted: true`, the market file marks the item `defaulted`, and Discord gets a warning. Not hidden.
10. **`usable`** = none of `zero_bid, zero_ask, crossed_market, wide_spread` (config `quality.unusable_flags`). `stale_last`, `iv_divergence`, `parity_violation`, `missing_oi` are informational. `wide_spread` requires **both** spread/mid > 50 % **and** spread > $0.10, otherwise every penny-wide far-OTM option would be flagged. Rows are never dropped by quality checks, only by the configured DTE/moneyness filters.
11. **(deviation) Broken-chain test.** The prompt's example was ">50 % zero bids". Measured live on SPY, 139 of 2,758 rows (5 %) legitimately have zero bid (far OTM) and 0 % do within ±3 % of spot, so a whole-chain 50 % rule would be wrong in both directions. The implemented rule: during market hours, reject if the chain is empty/has < 50 rows, or if > 50 % of rows within ±3 % of spot with DTE ≥ 1 have zero bid, or every such ask is zero. After the close the test is skipped (quotes are legitimately stale). Rejected chains are **not stored**, the heartbeat records `failed`, and Discord gets a failure.
12. **Parity check** per (expiry, strike): |(C−P) − (S·e^{−qT} − K·e^{−rT})| > 1.0 × (call spread + put spread) + $0.10. Both rows are flagged. Pairs without two-sided quotes are skipped (not flagged).
13. **Pinned contracts.** Before each snapshot, every leg of every alert/fill whose expiry is still in the future is captured regardless of the filters (even if the position was theoretically closed – the tracker may still need later marks). Underlyings that appear only in alerts (e.g. an earnings-straddle name) get a **pin-only** snapshot of just those contracts.
14. **Storage.** zstd level 9 parquet, `float32` for derived columns. **Measured size per day** (live Yahoo pull, 2026-11-04 00:20 ET, filters DTE 0-60 & ±15 %): SPY 164,889 B (2,758 rows), QQQ 157,017 B (2,581), IWM 92,838 B (1,430) ⇒ **0.83 MB/trading day for both slots of all three** ⇒ ~17 MB/month, ~209 MB/year. (After-hours quotes; the row count is set by the filters, so market-hours files should be the same order of magnitude.) The size guard measures `max(data/ + compacted/, data/ + .git)` against 800 MB: with monthly compaction (history keeps the daily blobs, so the server-side repo ≈ 2× the data) the warning fires around **2028-10**; if you stop compacting it fires around **2030-09**.
15. **(deviation, honest caveat) Compaction does not shrink `.git`.** It merges daily files into one parquet per underlying-month (fewer files, faster loads, row counts verified before any daily file is deleted, idempotent), but git history keeps every old blob. To actually bound repo size you would tighten the filters, drop `extra` tickers, or archive old months to another repo/release. The guard says so in the Discord warning.
16. **No OptionsDX exporter.** I searched `~/trading`, `~/Claude Trading Desktop`, `~/Documents`, `~/Desktop`, `~/Downloads` (depth ≤ 4) for `*optionsdx*` / `*options_dx*` and found nothing, so there is no verified column layout to match. `odj export` supports `csv` and `parquet` only.
17. **Backfill** is Alpha Vantage `HISTORICAL_OPTIONS` only, stored with `slot=eod` (`1600.parquet`), and **`UNVERIFIED-LIVE`** (no key available). AV's payload has no underlying price, so spot is inferred by put-call parity at the ATM strike and flagged `underlying_price_inferred`. Without a key or plan access it prints a message and exits 0.
18. **`SyntheticProvider`** (tests/selftest only) is refused by `odj snapshot` unless `ODJ_ALLOW_SYNTHETIC=1`, so fake chains cannot leak into the real dataset.

## Module B – journal

19. **Identifiers.** Alerts: `{bot}-{YYYYMMDDTHHMMSSZ}-{n}` (prefix must equal `bot`). Issue-form records: `fill-gh{N}`, `exit-gh{N}`, `skip-gh{N}` (re-processing an issue is a no-op). CSV imports: `fill-rh-{sha1(row digests)[:12]}` (deterministic ⇒ re-import is a no-op; identical rows inside one file get an occurrence counter). Same id + identical content = idempotent no-op; same id + different content = loud `ConflictError`.
20. **Referential integrity** is enforced on write: a fill's `alert_id`, an exit's `fill_id` and a skip's `alert_id` must exist; an exit cannot close more contracts than remain open.
21. **Sign convention everywhere** (per share): credit +, debit −, for the alert, the fill *and each exit's cash flow* (closing a credit spread is negative; expiry worthless is 0). P&L/share = entry_net + exit_net. Entry slippage = fill − alert; exit slippage = actual − theoretical; negative = worse. `max_profit`/`max_loss` are dollars per contract.
22. **Exit-rule semantics** (written into the schema): `profit_target_pct_of_credit = p` ⇒ exit when unrealized P&L ≥ p % of |alert_net_price| (credit received, or debit paid for debit structures); `stop_loss_multiple_of_credit = m` ⇒ exit when P&L ≤ −m × |alert_net_price| (i.e. *loss* equals m × credit – **not** "debit to close equals m × credit"; if your bots mean the latter, convert m→m−1 in the bot); `dte_exit = d` ⇒ first snapshot with ≤ d calendar days to the earliest expiry; `time_exit` = ISO datetime or integer days held. Priority at one snapshot: stop, profit, dte, time; earlier snapshots always win.
23. **Shadow tracker** (pure functions): option-only, single-expiry structures; stock legs, multi-expiry or a zero alert price ⇒ `unmarkable` with the reason. A leg that never appears in any later snapshot ⇒ `unmarkable` (no interpolation, ever). Snapshots with a missing/invalid/crossed quote are *gaps* (counted), not filled in. Settlement uses the underlying price at the **close-slot snapshot on expiry date** (~15:50 ET) as a proxy for the official settlement price; if expiry has passed with no such snapshot the alert is `unmarkable` rather than guessed. `mark_mode=conservative` closes long legs at the bid and short legs at the ask. The intraday-touch miss is pinned by a test.
24. **Metrics.** Capture ratio = Σ realized (after fees) / Σ theoretical (before fees, × contracts) over closed, taken, markable trades (ratio of sums, not mean of ratios). Slippage-vs-edge = mean round-trip slippage cost / mean theoretical edge over *the same trades*; red flag only when n ≥ min_sample and ratio > 0.5, with a plain-English sentence. Calibration: configurable buckets (1-40, 41-60, 61-80, 81-100), win rate = theoretical P&L > 0, Spearman ρ with a percentile bootstrap CI (2,000 resamples, fixed seed ⇒ reproducible); if the CI includes zero the report says the score is *not demonstrated to carry information*. **Samples needed:** `min_sample` = 30 alerts with a closed shadow outcome per metric/bucket; a bucketed calibration needs ~30 per bucket (≈120 scored alerts) before the bucket rows mean anything.
25. **Realized P&L attribution.** Entry fees are allocated to exits pro rata by contracts. Positions are derived, never stored.
26. **Robinhood import.** Dates only (no times) ⇒ timestamps are set to 12:00 ET and `ts_precision: "date"` excludes them from latency stats. Legs on the same date/underlying/quantity/expiry are one spread (classified into put/call credit spread, iron condor, straddle/strangle, long/short single, else `other`); fees = cash-from-prices − sum(Amount). Match score = 0.55 × leg overlap + 0.15 × structure + 0.20 × time proximity + 0.10 × size; ≥ 0.80 and ≥ 0.05 ahead of the runner-up ⇒ matched, otherwise **parked** in `journal/unmatched.json` (ambiguity is never forced). Items that duplicate a manually-logged fill (same alert, contracts, ET date) are skipped.
27. **Issue forms.** Template field labels *are* the parser's contract (a test enforces equality). The workflow runs only for `issue.user.login == repository_owner` **and** a `[fill]`/`[exit]`/`[skip]` title (labels are not auto-created by GitHub, so they are not trusted as a gate); Python re-checks the owner. The body is parsed with string operations only and reaches the workflow solely through the event *file*. A known heading appearing twice (free text imitating a field) ⇒ the form is rejected as ambiguous. Comment text never echoes the user's notes.
28. **Alert transport.** `repository_dispatch` with one JSON-string property (`{"alert": "<json>"}`) because of GitHub's 10-property cap. Payload cap 200 kB.
29. **(deviation) Concurrency groups.** The prompt asks for a concurrency group with `cancel-in-progress: false`. GitHub keeps **only one pending run per group** and cancels older pending ones even then, so a shared group would silently *drop* the middle of three simultaneous alerts. `ingest-alert.yml` therefore uses a per-run group (nothing is ever cancelled) and race-safety is handled where it belongs, in git: journal JSONL is `merge=union`, and `odj ci publish` does commit → fetch → `rebase -X theirs` → semantic merge of `status/heartbeat.json` → regenerate summary → push, with bounded retries and jitter. A test pushes from four clones concurrently and asserts every record survives.
30. **Token permission.** The bot-side dispatch token is a fine-grained PAT scoped to this one repository. GitHub documents *Contents: Read and write* as the permission for creating a repository-dispatch event; that is broader than I would like (it could also push code to this private repo), so keep it only in the bots' Actions secrets. A narrower alternative (a `workflow_dispatch` on `ingest-alert.yml` with `Actions: write`) exists if you ever want it; the prompt specified `repository_dispatch`, so that is what is built.
31. **Discord** posts only on failures, warnings (defaulted inputs, low usable %, size) and the weekly report; no per-snapshot success pings (the watchdog covers absence). One helper: ≥ 1.2 s between posts, 429 retry, 1,900-char truncation, `allowed_mentions` disabled, URL never logged.
32. **Watchdog** is generic (`common/staleness.overdue(expected, successes, now, grace)`): it takes expected run times and success times, so other bots can reuse it. Snapshot expectations come from the real calendar (weekends, holidays, half-day 12:50), grace 45 min, lookback 30 h. A red run posts to Discord and fails the workflow so GitHub also notifies you.
33. **Summary JSON** (`data/summary/latest.json`, `schema_version: 1`) is rewritten after every snapshot and every ingest and is validated against `schemas/summary.schema.json` before writing; rolling-metric failures are recorded in the file (`error`) instead of breaking ingestion.
34. **Watchdog go-live guard.** `watchdog.not_before_utc` (config/journal.yml, set to 2026-11-04 12:00 UTC when the repo went live) suppresses expectations that predate go-live, otherwise the first watchdog run would "discover" slots that could never have run. After that instant any missing slot, late slot, recent failure or missing weekly report alarms.
35. **Live-test hygiene.** I exercised the real GitHub workflows (dispatch, issue forms, snapshot) with `test: true` records, then removed the records, the test snapshot, the market file and the heartbeat in follow-up commits. Git history therefore contains those commits and one ~50 kB test parquet; the working tree is pristine.
36. **Git auth in this environment.** `git push` over https had no credential helper, so pushes used a one-off `-c credential.helper='!gh auth git-credential'`; nothing was written to your global git config. The Actions workflows push with the job's own `GITHUB_TOKEN` (contents: write).
